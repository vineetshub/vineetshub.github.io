Ringer Game

What it does: A sports-themed party game where everyone receives the same secret player except a hidden ringer. Players exchange clues and try to spot who is bluffing.

Purpose: A browser game combining my interests in sports and interactive software. It offers a quick example visitors can actually try.

Design challenge and approach

The main design problem is revealing roles without spoiling the game. Separate setup, role-reveal, and discussion screens guide players through the round.

Play the game →

Quant Stock Prediction & Backtesting Finance

What it does: A financial-data project that brings together a Django backend, stock-price data, a prediction model, and backtesting reports. Backtesting means checking an approach against historical data.

Purpose: A way to connect my interests in software engineering and finance by following data from an external API through to an analysis.

Design challenge and approach

The engineering focus is connecting data collection, storage, and reporting in a consistent workflow. The résumé linked above describes the API integration and deployment work. Historical results and model predictions do not guarantee future performance.

View repository →

Insider Trading Data Pipeline Finance

What it does: A Python dashboard for exploring publicly reported insider transactions from SEC filings, with filters, charts, and CSV exports.

Purpose: The purpose is to turn a large collection of filings into information that someone can explore without reading each filing individually.

Design challenge and approach

Data source and context matter. The interface separates sample data from API data and provides ticker, trade-type, and date filters so users can examine a specific question.

View source and documentation →

Connections Reimagined Game

What it does: A word-grouping puzzle inspired by Connections. Players look for hidden relationships between words across themes such as space and literature.

Purpose: A web project exploring how a game can encourage critical thinking and make learning feel more interactive.

Design challenge and approach

The challenge is giving players useful feedback without revealing the answer. The project uses HTML, CSS, and JavaScript; its README describes adaptive AI gameplay as a planned next step, rather than a completed feature.

View source and project notes →

RU OnTrack Student tools

What it does: A Rutgers schedule-planning project designed to help students organize a semester around their academic progress and previously completed courses.

Purpose: It addresses a problem I recognize as a student: course planning involves more than finding classes that sound interesting.

Design challenge and approach

The design challenge is turning academic inputs into a clear recommendation. The project organizes degree level, student standing, and completed-course information around the planning process.

Lyft Backend Engineering

What it does: A backend engineering job simulation based on an unfinished vehicle-rentals project.

Purpose: A structured learning experience for practicing software design and testing. It was a virtual simulation, not a Lyft internship.

Design challenge and approach

I drafted a UML class diagram, refactored the inherited codebase to match the design, and added functionality with unit tests. Tests helped connect the reorganization to expected behavior.

RU Eats Prototype

What it does: A SwiftUI prototype exploring Rutgers dining-hall navigation and wait-time screens.

Purpose: A student-focused mobile project about making everyday dining information easier to reach.

Design challenge and approach

The design focus is moving between a dining-hall list and individual screens. The public code still contains placeholder wait-time and login logic, so this is presented as a prototype rather than a live dining service.

Financial Charts Dashboard Prototype

What it does: A dashboard prototype that connects a Next.js frontend to a Django API and presents financial-style charts.

Purpose: A project for exploring how a web interface and backend work together to make data easier to inspect.

Design challenge and approach

Keeping chart formats consistent across the API and frontend is the central engineering concern. The documented version uses fixed sample data, containerized setup, and tests; it does not demonstrate a live trading strategy.
